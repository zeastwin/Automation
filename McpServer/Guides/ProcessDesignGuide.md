# Automation AI 流程设计指南

> 这是 Automation 复杂流程设计的唯一按需知识源。
> 内容由通用不变量和可组合功能块组成；其中场景写法吸收了 `1HSG下料` 等历史项目中经甄别的流程组织经验。
> 历史项目只提供职责和阶段参考，不提供当前字段、资源、运行行为或安全结论。

## Core：当前功能块的最短可靠路径

- 先确定可观察目标、完成证据、外部副作用和失败出口；等待补充超时，重试补充幂等与耗尽出口。
- 当前字段、行为、资源和启动条件分别以 Schema、Behavior、资源工具和 Readiness 为准，历史写法不覆盖当前事实。
- 相关资源存在但缺少点位、角色、极性或终态证据时，这是待补事实，不是该功能无需实现的证据；替代机构会改变目标含义时先询问，或用占位保留原目标。
- 工站已有实际轴但缺少目标点位时，模型规划有业务含义的点位名并先写入运动流程；名称可登记为待示教点位，坐标由人工示教。这个缺口进入 Readiness，不阻断结构保存，也不允许猜坐标后运行。
- 一个预演只需形成可独立审查和保存的阶段。简单流程可以完整创建；复杂、带回环或资源未决时先提交 `autoStart=false` 的安全骨架，再按稳定 ID 逐块补齐。
- 缺少运行资源或真实结果条件时，使用一等 `config.placeholder` 保持 `incomplete`；只占位未知事实，已知的分支、清理和出口仍保留为结构。占位不弹框、不运行，也不能用 `message` 冒充控制流。
- “重试 N 次”表示首次失败后最多再执行 N 次，最多总尝试次数为 `1+N`。真实指令支持 `RetryCount` 时优先使用它；需要流程级重试时，用尝试次数变量、结果分支和回跳直接表达。
- 重试、普通计数、遍历和生产节拍循环都使用同一组基础控制流原语；模型按业务语义决定变量、分支和出口，平台不按表面形状自动分类或改写。
- 每个阶段按“解析必要事实 → 预演 → 确认 → 提交 → 回读验证”闭环推进，不在首次预演前展开整单实现。

## Core：所有功能块共享的不变量

`core` 由服务端自动附带，不需要调用方重复请求。

### 权威边界

- 用户目标决定期望行为和业务取舍。
- 当前语义/原生 Schema 决定字段结构和合法值。
- 当前 Behavior/Operation Guide 决定指令运行语义。
- 当前资源工具决定变量、IO、工站、点位、通讯和报警事实。
- Readiness 与启动闸门决定流程能否运行。
- 本文只指导职责划分、阶段组织和闭环设计；历史案例不能覆盖上述事实。

### 最小设计摘要

只保留当前功能块真正影响实现的四项：可观察目标、完成证据、外部副作用、失败出口。涉及等待时补充超时，涉及重试时补充幂等与耗尽出口；无需在工具调用前生成固定格式的完整设计卡。

### 核心设计准则：六条通用不变量

1. **命令不等于完成。** 重要动作采用“检查—命令—反馈—验证—提交”；状态只在完成证据成立后提交。
2. **等待必须有边界。** 设备反馈、子流程终态和外部响应具有超时与异常出口；固定延时只表达工艺、去抖或节拍时间。
3. **不确定状态安全收敛。** 涉及设备、人员或产品风险时，无法证明继续安全就停止受影响动作并明确报警。
4. **恢复返回稳定节点。** 不跳回故障动作中间位置；自动恢复次数有限，并以重复执行安全为前提。
5. **副作用先判断幂等。** 写入、上传、下发、放料和状态提交无法证明可重复时，进入查询确认、人工恢复或确定停止。
6. **历史写法必须适配。** 只借鉴职责和阶段；旧名称、地址、参数、ID、跳转、报警模式和禁用配置不得照抄。

资源缺少精确目标、业务角色、电气极性或终态反馈时，只能确认当前事实不足。不能把事实缺口当作舍弃相关功能的理由；改用另一机构会实质改变用户目标时，先询问用户或用 `config.placeholder` 保留原目标。单个输入未激活只证明该输入未激活，不证明机构已经到达相反机械终态。

### 重试次数的统一语义

- “重试 N 次”统一表示首次尝试失败后最多再执行 N 次，因此最多总尝试次数为 `1 + N`。原生通讯指令的 `RetryCount` 也采用这个语义。
- 手工流程优先使用 `attemptCount` 表示已经发起的总尝试次数：每次动作开始前加一，失败后仅当 `attemptCount < maxAttempts` 才返回重试；若用户要求“重试 3 次”，则 `maxAttempts=4`。
- 流程级重试显式保留业务尝试入口、结果判断、成功出口、耗尽出口和每轮所需的业务变量清理。结果条件未知时可使用独立 `config.placeholder` 保留计划成功/失败出口，但不伪造判断结果。
- 平台不提供重试宏，也不根据“计数器 + 后向跳转”的表面形状拒绝或改写回环。模型使用相同的变量、分支与跳转原语表达重试、遍历、轮询或生产节拍，并由 ChangeSet 预演检查结构。
- 若因现有变量只能使用 `retryCount`，它必须表示已经发起的额外重试次数：首次失败时先判断 `retryCount < maxRetries`，成立后再加一并重试。不得“先加一再与 maxRetries 做小于比较”，否则会少执行一次重试。
- 设计说明、变量名称、分支比较和验收用例必须使用同一口径，同时列明最大重试次数和最大总尝试次数，避免把“3 次重试”误写成“总共 3 次”。

### 结构尺度

- `Proc` 表达可以独立启动、等待、停止、完成或恢复的任务。
- `Step` 表达一个业务阶段，具有明确目的、入口、出口和异常影响。
- `OperationType` 表达原子执行、等待或控制流语义；字段仍以当前 Schema 为准。
- 功能块不是持久化对象。一个功能块可以成为一个 Step、多个 Step，或在需要独立生命周期时成为子 Proc。

## 生命周期块：复位、初始化与启动

### 适用范围

全机或子系统复位、初始化、启动请求、启动调度和系统状态建立。

### 职责

- 复位负责建立可启动其他任务的稳定状态。
- 启动负责检查全局条件、准备本周期状态和协调工站，不承载所有具体机构动作。
- 按钮/请求检测只识别触发与释放，不把“按钮按下”当作复位或启动已经完成。

### 参考骨架

```text
复位：锁定入口 → 初始化本周期状态 → 执行器收敛 → 运动对象回原/安全位
    → 建立通讯可用性 → 验证完成证据 → 提交就绪

启动：检查复位/互锁/资源 → 清理上周期结果 → 准备本周期任务
    → 启动目标流程 → 等待并判断真实终态 → 提交运行状态
```

### 历史经验的吸收方式

`1HSG下料` 的复位流程按寄存器、气缸、工站回原和通讯连接分阶段，这种阶段意识值得保留；实际顺序、回原路径、完成反馈和通讯对象全部按当前项目重建。启动流程中的旧“流程操作”必须先核对其实际行为，再判断是否需要子流程等待闭环。

## 调度块：主流程、子流程与并行协调

### 适用范围

主调度、工站启停、异步子流程、多流程并行和共享任务协调。

### 职责

- 调度层准备任务、启动目标、等待终态并消费结果。
- 工站层拥有自己的机械动作、反馈和异常收敛。
- 共享状态具有唯一写入方、清理时机和提交时机。

### 参考骨架

```text
检查目标流程可启动 → 清理上次结果 → 写入本次任务
→ 启动目标流程 → 等待 Ready/明确终态
→ 判断结果 → 成功继续或协调其他流程停止/收敛
```

### 特有约束

- “启动成功”只证明接受启动请求，不证明任务完成。
- 同一目标流程未结束时不得假设可重复启动。
- 并行流程明确设备所有权、共享资源、等待关系和一个流程失败时其他流程的收敛策略。
- 当前流程状态枚举和等待模式从行为 Guide 获取，不沿用历史项目的状态名称或跳转位置。

## 互锁块：门禁、光栅与动作前置条件

### 适用范围

安全门、光栅、急停相关状态、工件存在、机构避让、对向反馈和动作许可。

### 职责

- 工业安全链路负责硬件安全动作；软件流程只承担平台允许的检测、协调停止和报警。
- 每个危险动作开始前检查与该动作直接相关的安全条件。
- 条件失效后明确受影响对象，不用一个通用标志模糊替代设备状态。

### 参考骨架

```text
读取当前条件 → 校验信号组合与机构位置 → 条件成立时授予本次动作许可
→ 执行动作期间持续由安全链路保护 → 条件失效时停止/收敛并报警
```

### 特有约束

- IO 的 true/false 只表示精确点位的逻辑激活状态，不统一表示安全、危险、原位或工作位。
- 门禁、光栅是否属于工业安全以及影响哪些运动对象，必须来自当前安全设计。
- 历史项目中两套相近门禁流程只能提示“先确认设备范围和唯一职责”，不能仅按名称合并或复制。
<!-- process-design:interlock:end -->

## 执行器块：IO、气缸、阀与真空

### 适用范围

单/双线圈气缸、阀、夹爪、真空取放以及其他输出—反馈执行器。

### 可组合子块

- **动作前检查**：互锁、对向位置、压力/真空状态和目标有效性。
- **输出命令**：按当前电气契约处理单线圈、双线圈或保持输出。
- **反馈等待**：等待目标反馈，检查对向反馈和超时。
- **结果提交**：反馈成立后再更新夹持、占用或产品状态。
- **安全收敛**：失败后保持、关闭或释放由现场安全和产品保护要求决定。

### 参考骨架

```text
检查互锁和当前位置 → 设置目标输出 → 等待目标反馈
→ 校验对向反馈已解除 → 提交动作结果
→ 超时/矛盾反馈时执行现场允许的收敛并报警
```

### 特有约束

- 双线圈或互斥输出的先后顺序来自当前电气契约。
- 真空反馈未成立时不得提交“已取料”；释放反馈未成立时不得提交“已放料”。
- 有直接反馈时不用固定延时代替到位证明。

## 运动块：轴、工站、回原与安全路径

### 适用范围

单轴、多轴工站、机器人走点、轨迹、回原、动态目标和偏移运动。

### 可组合子块

- **运动资格**：回零、使能、报警、停止状态和动作互锁。
- **目标规划**：点位存在、动态值有效、范围和坐标系正确。
- **点位落地**：没有现成目标时，先从业务目标规划名称并用于流程，再登记为待示教点位；人工示教前只完成结构，不具备运行资格。
- **安全过渡**：按机构结构进入安全位或离开危险区域。
- **目标运动**：发出运动并等待当前行为契约定义的完成。
- **终态验证**：停止、到位、关联反馈和目标状态一致。

### 参考骨架

```text
检查资格与互锁 → 计算并校验目标 → 进入安全过渡位置
→ 执行目标运动 → 等待完成 → 验证终态
→ 需要时返回安全位置 → 提交运动结果
```

### 历史经验的吸收方式

历史项目把走点、偏移、轨迹和反馈动作保持在流程中可见，适合作为可调试性参考。不能根据“运动指令数”和“等待运动数”的差值判定旧流程缺陷；必须逐段确认当前指令是同步还是异步，以及完成、超时和停止语义。
<!-- process-design:motion:end -->

## 取放块：取料、放料与正常/NG 分流

### 适用范围

机器人或机构取料、夹持、移载、正常品/NG 品分流、料盘放置和产品结果提交。

### 组合关系

取放块通常组合 `interlock + motion + actuator`，并根据业务需要接入 `identify`。它描述一次完整机械任务，而不是重复定义底层指令规则。

### 参考骨架

```text
确认工件与目标 → 到安全过渡位 → 进入取料位
→ 夹持/真空并验证取料 → 离开危险区域
→ 根据已确认结果选择正常或NG目标 → 进入放料位
→ 释放并验证 → 返回安全位 → 提交本周期结果
```

### 历史经验的吸收方式

`1HSG下料` 的收料机器人把“取料—正常盘放料—NG 盘放料”分为明确阶段，适合作为结果路径显式化的参考。当前实现应根据正常/NG 路径是否需要独立停止、重试或恢复，决定使用 Step 还是子 Proc；点位、偏移、夹持策略和恢复位置全部重新获取。
<!-- process-design:pick-place:end -->

<!-- process-design:transfer:start -->
## 搬运块：输送、载具、升降与料仓交接

### 适用范围

输送线、载具搬运、升降模块、空/满料仓、上料/收料模块，以及两个工站间的物料交接。

### 可组合子块

- **请求**：上游声明本周期物料与交接目标。
- **许可**：下游确认空闲、互锁和容量。
- **搬运**：拥有设备的一方执行输送、升降或定位。
- **接收证明**：下游反馈物料已进入稳定位置。
- **提交与清理**：更新占用状态并清理本周期握手。

### 参考骨架

```text
检测物料/请求 → 检查下游许可与本机互锁 → 锁定本周期交接
→ 执行搬运 → 等待离开和到位反馈 → 双方确认结果
→ 提交占用状态并清理请求/许可 → 返回下一周期入口
```

### 历史经验的吸收方式

历史项目把收料模块、载具、搬运、回流、升降、空料仓和满料仓拆成独立职责，适合学习设备所有权。旧项目中的共享标志、延时和循环跳转不能复制；当前流程必须重新确定唯一写入方、反馈组合、容量边界和异常时物料归属。
<!-- process-design:transfer:end -->

## 识别块：扫码、RFID 与物理对象绑定

### 适用范围

条码、二维码、RFID、产品型号识别、重复码检查以及识别结果驱动的路径选择。

### 职责

- 明确本次识别对应哪个物理工件或载具。
- 读取前清理旧结果，成功后一次性提交本周期身份。
- 读取成功、格式有效、业务接受和产品类型判断是不同结果。

### 参考骨架

```text
确认工件已到识别位 → 清理旧身份与结果 → 触发读取
→ 等待本次响应 → 校验格式/长度/重复性
→ 绑定当前物理对象 → 判断产品类型或后续路径
→ 提交身份；失败时保留对象可恢复状态并进入明确出口
```

### 历史经验的吸收方式

`1HSG下料` 的扫码流程把物料存在、扫码、产品类型和后续分流联系起来，说明识别结果必须与物理对象绑定；但其 213 条指令集中在单步骤，不作为结构模板。新流程应按“触发—读取—校验—绑定—提交—失败”拆成可解释阶段。

## 外部事务块：MES、TCP、串口与请求响应

### 适用范围

MES 查询/上传、TCP、串口、PLC 数据事务、第三方设备请求响应和外部处理函数。

### 职责

- 调用方准备任务、启动事务、等待确定终态并消费结果。
- 事务块完成一次连接检查、发送、接收、解析、业务判定和结果提交。
- 发送失败、接收超时、协议错误、业务拒绝和连接中断分别处理。

### 参考骨架

```text
清理旧结果 → 检查连接和请求参数 → 发送本周期请求
→ 等待响应/超时 → 校验协议格式 → 判断业务结果
→ 提交事务结果 → 自然完成
```

### 特有约束

- 重连只恢复连接；当前业务事务仍需重新执行或查询确认。
- 通讯重试次数、间隔和响应条件从当前行为契约获取。
- 写入、上传、下发启用重试前必须证明远端允许重复执行。
- 历史“发送处理消息”只有在处理器输入、输出、异常、停止和重复调用契约完整时才能迁移。
<!-- process-design:transaction:end -->

## 持续监控块：状态呈现与物料异常

### 适用范围

状态灯、门禁状态呈现、满盖盘、堆料、缺载具、设备健康和其他持续观察条件。

### 职责

- 读取事实、判断状态变化并通知受影响流程或更新呈现。
- 不直接伪装被监控机械动作已经完成。
- 多状态呈现定义明确优先级，避免多个分支互相覆盖。

### 参考骨架

```text
读取/等待条件变化 → 判断当前状态与上次状态
→ 无变化时进入可停止的短周期等待
→ 变化时更新呈现或通知受影响流程
→ 必要时等待相关流程收敛
→ 条件恢复后按授权清除状态
```

### 历史经验的吸收方式

历史项目把状态灯、门禁、满盖盘、堆料和缺载具分别建模，适合学习持续监控与生产节拍分离。是否应合并由设备范围、更新频率、停止影响和状态所有权决定，不能只根据名称相似度判断。

## 恢复块：寻料、重入与有限恢复

### 适用范围

异常后收敛、启动时寻料、中断重入、有限重试、重新定位以及人工恢复入口。

### 职责

- 先读取真实物理状态，再选择继续、撤回、重试或停止。
- 恢复目标是反馈可确认、可以决定下一步的稳定节点。
- 无法唯一解释物理状态时保持停止并报警。

### 参考骨架

```text
冻结新任务 → 读取位置、夹持、传感器和未完成事务
→ 校验状态组合 → 选择现场允许的稳定目标
→ 执行有限撤回/寻料/重新定位 → 等待直接反馈
→ 清理上周期状态 → 返回就绪、人工继续或停止结果
```

### 历史经验的吸收方式

历史项目单独建立“启动时寻料”，说明设备启动状态可能不同于空机初始状态，这个问题意识值得吸收。旧流程中大量禁用项和“自动处理”只作为待甄别事实；当前恢复策略必须重新证明安全前提、次数边界、成功证据和耗尽出口。

## 自定义函数块：流程可见性与代码边界

### 适合进入函数

- 纯计算、格式转换和协议编解码。
- 多流程复用且不直接承担机械安全的业务算法。
- 已有稳定接口的第三方 SDK 适配。

### 应保留在流程图

- 安全和前置检查。
- IO/设备反馈等待。
- 轴、工站和取放动作。
- 子流程启动、等待和终态判断。
- 超时、报警和恢复路径。

### 函数流程契约

使用前明确输入、输出、副作用、超时、异常、内部重试、重复调用安全、停止响应和返回后的流程分支。函数不能用来隐藏未知资源、规避 Schema，或把多个未验证机械动作包装成一个“成功”返回值。

## 审查块：创建前、预演后与提交后

### 创建前

- [ ] 当前功能块的目标、完成证据、副作用和失败出口已明确；等待或重试所需的附加边界已按需补充。
- [ ] 已选择所需功能块，没有为简单动作强行建立空壳 Proc。
- [ ] 当前资源和关键行为契约已经读取；项目特有参数没有从历史案例猜测。

### 预演后

- [ ] Proc/Step 职责和名称能表达业务阶段。
- [ ] 重要动作形成检查、命令、反馈、验证、提交闭环。
- [ ] 分支、循环、等待、子流程和外部事务都有终止或异常出口。
- [ ] 自动恢复和外部写入已判断重复执行影响。
- [ ] 预演警告、阻塞和 `incomplete` 原因与用户目标一致。

### 提交后

- [ ] 使用返回的稳定 `procId/stepId/opId` 回读关键结构。
- [ ] `validate_proc` 已区分结构有效与运行就绪。
- [ ] 禁用配置仍作为事实可见，且没有被自动当作缺陷或推荐写法。
- [ ] 未经用户授权不把保存成功提升为实机运行成功。
