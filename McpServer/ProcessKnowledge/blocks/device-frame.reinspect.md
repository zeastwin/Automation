# 复检/检测设备框架

## 设备画像

对已完成工艺的工件执行质量复判的设备或工位组：来料缓冲后进入检测工位，按检测项执行视觉/测量作业，NG 分流（抛料或重测复检成对），OK 汇合出站上报。既可作为独立复检机，也可作为整机内的复检工位（点胶机、拆盖板机的复检段）。

## 功能单元构成

| 单元 | 职责 | 典型流程 | 引用功能块 |
|---|---|---|---|
| 复检缓冲 | 来料缓冲、状态推进 | 复检缓冲区流程 | transfer.pipeline-station-triad |
| 检测作业 | 视觉检测/测量、项目判定 | 复检作业流程+复检工作台 | vision.positioning-and-correct |
| NG 分流 | 抛料复检 NG、抛料仓满处置 | 抛料 复检NG流程 | quality.reject-and-divert |
| 重测成对 | 首判 NG→重测复检二次判定 | 复检流程+(重测)复检流程 | quality.dry-run-and-grr-pair 的成对结构 |
| 数据处理 | 检测结果记录、判定数据整理 | 复检工站数据处理流程 | transaction.submit-trace-record |
| 工位复位 | 复检工站独立复位 | 复检工站复位流程 | reset.system-and-station-reinit |
| 空跑配套 | 复检空跑旁路上报 | 复检作业(空跑)流程 | quality.dry-run-and-grr-pair |

## 单元间衔接

物料流：来料→复检缓冲区→检测作业（多检测项按序判定）→判定分叉：OK 出站 / NG 抛料 / 待重测进重测复检。判定流：首检 NG 不直接抛料，先进重测复检二次判定，重测仍 NG 才抛料（成对结构）；也可按用户要求首判即分流。信息流：检测结果随载体身份写入记录，出站上报 MES。

## 框架变化点

独立复检机 vs 整机内复检工位；有无重测复检成对（首判即抛 vs 二次复判后抛）；检测项数量与判定顺序；抛料位独立 vs 与其他工位共用；有无空跑配套。

## 搭建顺序

复位族 → 复检缓冲三件套 → 检测作业（先运动取像后判定）→ NG 分流抛料 → 重测成对（如需要）→ 数据处理+出站上报 → 空跑配套。

## 完成证据

OK/NG/重测三分支各有实物去向且账目与判定结果一致；重测路径只接收首判 NG 的工件，二次判定后必达终态（OK 出站或抛料）；抛料仓满时停止进料并人工处置，不继续堆积。

## 反模式

- **判定与去向脱账**：判 NG 的工件出现在 OK 出站，三分支去向与判定结果对不上。分支账目是完成证据。
- **重测无次数上限**：NG→重测→NG→重测无限循环。重测上限后必达终态。
- **首判即抛未确认**：用户没确认就按首判 NG 直接抛料，跳过二次复判。判定策略是工艺决策需确认。
- **检测项顺序硬编码**：检测项与顺序写死，换产品要改流程。检测项配置化。
- **抛料仓满不停止**：仓满继续检测进料，NG 无处放堆积。仓满停止进料转人工。

## 黄金样例

> 来源：`BC拆盖板NS_V3.0.0_0922(立凯)` 的复检段（整机内复检工位形态）。

**复检段六件套落地**：复检作业、(重测)复检流程、抛料 复检NG、GRR、CCD生产模式、空跑——六个流程覆盖"首判→二次复判→抛料→统计→生产/验证成对"全部职责。

**判定流水线骨架**：复检作业（首判：视觉/测量按检测项判定）→ NG 则进 (重测)复检流程（二次复判，排除首判误杀）→ 重测仍 NG 进 抛料 复检NG（移出+留判定原因）→ OK 汇合出站。GRR 平行运行（复用检测动作+重复次数循环，结果单独记录）；CCD生产模式与空跑成对（旁路上报）。三分支（OK 出站/NG 抛料/待重测）每支都有独立流程承载，判定结果与实物去向一一对应。

**为什么重测独立成流程而不是分支**：重测复判的检测项可与首判不同（复核关键项），独立流程允许两者结构分别演进；若做成首判流程内的分支，判定标准两处维护必然漂移。这是"判定与执行分离"在复判场景的延伸。

## 幂等与甄别结论

框架只约束判定分叉与成对重测结构。旧项目"BC复检作业(无用)"弃用流程、复检作业数百指令复制文本、固定检测项参数不吸收；缓冲三件套+成对重测+NG 抛料闭环+工位复位分层被保留。判定顺序、重测次数上限属于工艺决策，按用户目标配置，不从旧项目默认。
