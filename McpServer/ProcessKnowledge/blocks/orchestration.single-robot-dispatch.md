# 单机器人调度与仓位记录

## 可观察目标

一台机器人服务多个流向（取来料入静置、取静置料放 A 机台、放 B 机台）时，由独立调度流程决策去向、执行流程各自完成搬运：调度器按下游要料信号与可取/可放仓位选择分支，串行启动对应执行流程（等待其他执行流程就绪后才启动，保证机器人独占）；仓位占用记录（可取/可放位置）由选定载体维护，流程读写并校验删除成功。

## 适用边界

适用于单机器人多任务、共享静置台/料仓等中间缓存需要仓位记录管理的场景。多机器人、或不需要仓位记录（硬件感应即可判断）时不适用。

## 当前事实与适配

需要：各流向执行流程、下游要料信号（虚拟 IO/实体 IO 双模，运行前确定一种）、仓位记录载体、载具位感应器名拼接规则。历史固定 A/B 两机台名称、固定偏移 50/60/70 不得复用；虚拟 IO 与实体 IO 两套实现只保留实际使用的一种。

仓位记录载体按当前项目事实选择一种，不重复建设：
- 流程变量/变量表：仓位数量少、只记占用序号时最简。
- 数据结构：每仓位一条（位置号、载具码、进料时间等）时用结构体数组，队列进出自然。
- 自定义代码：进站生成、出站删除、可放位置计算等逻辑复杂时委托代码维护，流程经消息/SDK 交互读写。
- 本地文件（json 等）：需跨启动保留或供外部系统读取时由代码侧落盘。

## 参考阶段

1. 调度循环：判断进料工作区可出料→查询可放/可取仓位→确认存在可取载具；再按要料信号区分"多目标同时要料"与"单目标要料"。
2. 分支串行：选定某流向后，先等待其余执行流程全部就绪（机器人空闲互斥），再启动目标执行流程并等待结束。
3. 执行流程前置三查：夹爪关闭且载具感应有料则先等待；读机器人当前位置做 X/Z 轴范围防呆，越界分层偏移回安全区。
4. 取/放作业：拼接目标感应器名→检测有料→计算取料点/过渡点/上方点索引→轨迹运动（过渡→上方→开爪→进给→闭爪→上方→安全位）；取放完成更新仓位记录（删除已取仓位）并校验删除成功，失败弹框。
5. 交接与记账：进站生成记录（位置号、载具码、各穴位码、时间）入选定载体；出站联动 MES 流程（等就绪→启动→完毕）后删除记录；放料完成置已放料标记、给料信号握手、记录 CT。

## 完成证据

同一时刻只有一个执行流程在运行；仓位记录数与实物载具数一致；每个出站载具都有进站记录。机器人被两流程同时驱动、或记录删除失败未报警均为失效。

## 失败、超时与恢复

仓位计算无可放位时等待；感应器检测无料自动跳下一位置；仓位删除失败弹框人工确认；调度分支等待要料信号超时回主循环重查。

## 反模式

- **两流程同时驱动机器人**：执行流程不等其他流程就绪就启动，机器人被两个流程交替命令。串行互斥（等就绪）是硬前提。
- **仓位记录只记不删**：出站后不删记录，仓位越占越多，可放位置计算永远失败。删除记录并校验删除成功。
- **删除失败静默继续**：记录删不掉就跳过，下轮重复生成同位置记录造成双份。删除失败弹框人工确认。
- **虚拟/实体 IO 双实现并存**：两套判断同时保留，改一处漏一处。运行前确定一种并删除另一套。
- **跳过位置防呆**：省掉 X/Z 轴范围检查，机器人越界撞机构。前置三查（夹爪、有料、轴位）不可裁剪。

## 幂等与甄别结论

调度决策与仓位记录读写幂等（删除失败有校验兜底）；执行流程串行由就绪等待保证。旧项目 A/B 机台硬编码、虚拟/实体双实现并存、固定偏移量未被保留；调度分流+串行互斥、位置防呆三查、感应器名拼接、记录删除校验、MES 出站联动被保留；旧项目"代码+json"的载体选择仅作为证据，新项目按仓位规模与交互需求选择最简载体。
