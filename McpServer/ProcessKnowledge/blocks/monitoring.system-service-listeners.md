# 系统常驻服务流程族（按钮代理/状态灯/报警上传）

## 可观察目标

一组自启常驻流程承担系统级服务：物理按钮（复位/启动/照明）由监听流程代理——按钮有效+释放去抖后按系统状态门控启动复位/启动总流程；状态灯控流程把系统状态映射到三色灯与蜂鸣器；报警上传流程把报警信息循环上报 MES/监控平台。业务流程不直接管按钮、灯与上报通道。

## 适用边界

适用于带物理按钮盒、三色灯、需要报警上报的整机。纯软件触屏设备无按钮/灯时不适用；门禁/安全回路不用本块（走 interlock.safety-gate-watchdog）。

## 当前事实与适配

需要：复位/启动/照明按钮输入与释放检测、系统状态枚举（含复位完成态门槛值）、三色灯/蜂鸣器输出、MES 报警上报通道（由代码侧提供）。历史固定"状态>=4"门槛数值不得复用，以当前状态机枚举为准。

## 参考阶段

1. 按钮代理：循环检测按钮信号→延时去抖→确认按钮有效且已释放→检查系统状态门槛（如已复位完成才允许启动）→等待目标流程就绪→启动→等待结束，然后回到监听。
2. 状态灯控：按系统状态（运行/暂停/报警/复位中）映射灯色与蜂鸣，状态变化即刷新；照明按钮做开关翻转并记录已开标志。
3. 报警上传：自启循环把当前报警信息经代码通道上传 MES，失败按报警忽略不阻断生产，上传后回到循环。
4. 系统报警流程汇总当前报警源并驱动声光，与报警处理流程（自启）配合人工复位。

## 完成证据

按钮按下且释放后目标流程恰被启动一次；状态灯与系统状态一致；报警产生后上报通道收到记录。按钮连击多次启动、灯色与状态不符均为失效。

## 失败、超时与恢复

按钮去抖期内重复信号被忽略；启动门槛不满足时提示系统状态而不启动；报警上传失败不阻断流程，只记录。

## 幂等与甄别结论

监听循环与灯控刷新幂等；启动目标流程由就绪等待保证不重入。旧项目固定状态门槛数值、固定弹框系统状态提示未被保留；按钮去抖+释放确认+状态门控、灯态映射、报警循环上报被保留。
