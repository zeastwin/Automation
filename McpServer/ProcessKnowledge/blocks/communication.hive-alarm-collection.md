# Hive 采集与报警上报

## 可观察目标

把设备侧报警与状态事件采集并上报到 Hive 采集系统，形成常驻的旁路观测链路；上报失败不影响本地生产流程。

## 适用边界

作为辅助诊断与数据采集的旁路存在；不承担工艺控制，不改变流程状态、安全停止或基础报警行为。采集代理类设备与全流程设备的 Hive 上报结构一致。

## 当前事实与适配

常驻形态两种并存：Hive采集系统常驻流程（建立连接、维持会话）+ HIVE 报警及状态采集循环（扫描事件并上报）；部分项目仅有采集循环。上报内容为报警事件与状态变化，不复制业务数据全量。采集链路故障只影响数据完整性，不阻塞生产。

## 参考阶段

1. 常驻维持与 Hive 的会话连接；
2. 循环扫描本地报警与状态变化，增量组装事件；
3. 上报并确认回执，失败留待重试；
4. 本地状态不因上报结果改变。

## 完成证据

报警发生后能在采集循环周期内出现在 Hive 侧；断链期间事件不丢（重试或留痕）；生产流程在采集链路故障时继续运行。

## 失败、超时与恢复

连接失败按周期重试；上报失败保留事件直到成功或被清理策略处理；采集循环异常只报警不影响主流程。

## 反模式

- **采集链路反控生产**：Hive 断链就把生产停下来或延迟上报工艺动作。旁路故障只影响数据完整性。
- **全量复制业务数据**：把生产数据全量塞进采集事件，主次不分且量大。只报报警事件与状态变化。
- **事件无标识去重**：同一报警每轮扫描重复上报，Hive 侧报警风暴。以事件标识去重。
- **失败事件直接丢弃**：上报失败就丢，采集数据静默缺失。保留事件直到成功或按清理策略处理。

## 幂等与甄别结论

同一事件重复上报需以事件标识去重。固定采集地址与周期参数不吸收；常驻会话+增量扫描的两层结构、旁路不侵主流程、事件不丢原则被保留。
