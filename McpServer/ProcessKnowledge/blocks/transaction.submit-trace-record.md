# 提交并确认追溯记录

## 可观察目标

每个符合条件的产品或槽位记录以稳定业务键提交到外部系统，并获得可回查的成功确认或明确失败分类；重复执行不会形成重复过站或重复上传。

## 适用边界

适用于MES检查、过站、Trace上传和本地事务服务。只写本地诊断日志或不影响业务状态的遥测不使用本块。

## 当前事实与适配

开始前获取提交资格、身份与槽位映射、目标接口、业务唯一键、请求和响应 Schema、超时、业务错误码、幂等能力、离线策略和生产放行规则。历史固定重试次数和结果字段编号不得复用。

## 参考阶段

1. 固定本次产品/槽位快照，过滤无需提交或身份无效的项目；资格判断结果必须可解释。
2. 使用产品身份、工站、业务动作和必要版本形成稳定幂等键，构造不可变请求。
3. 在有界时间内提交并保存请求摘要；响应必须与本次请求关联。
4. 区分成功确认、业务拒绝、通讯失败、超时和响应不确定。业务拒绝不做无条件重试。
5. 只有明确成功确认后才一次性写入已提交标记、回执和时间；失败保留请求与原因，按当前放行策略暂停、排队或人工处理。
6. 身份载体降级链：主载体（RFID）读取失败或功能关闭时，降级为代码生成的临时条码/载具码并按穴位级禁用与屏蔽NG规则登记，保证过站链不断链；RF 成功时按 OK/NG 分别计数，失败报警并置 NG 标记。
7. 进站后可按 MES 开关批量获取关联工站参数（复检 SN、各站超时、SN 位数检查等），获取失败按业务弹框处理，不静默放行。

## 完成证据

外部系统返回与业务键匹配的正向确认，本地成功标记、回执和身份快照原子保存，并能证明每个目标项目都得到终态。发送函数返回、写入暂停文件或增加重试计数都不等于完成。

## 失败、超时与恢复

通讯失败可使用同一幂等键有限重试；超时后若外部结果未知，先查询或对账，不能换新业务键重发。业务拒绝、身份缺失和工艺限制失败应进入可诊断终态。部分项目成功时逐项保留结果，不把整批简单重置为未提交。

## 反模式

- **换键重发**：超时后换新业务键重发，外部系统出现两笔过站。同一幂等键有限重试；结果未知先查询对账。
- **发送成功当提交成功**：接口函数返回 0 就置成功标记，不等业务确认。只有业务正向确认才写已提交标记。
- **业务拒绝当通讯失败重试**：MES 返回业务拒绝还反复重发。业务拒绝进可诊断终态，不重试。
- **整批重置**：批量提交部分成功后把整批重置为未提交，成功项被重复过站。逐项保留结果。
- **降级码当正式身份**：RFID 失败后生成的临时码没有按降级规则登记，追漏述断链还误以为身份有效。降级码按穴位级禁用与屏蔽规则登记。

## 幂等与甄别结论

重复进入先查询本地回执和外部状态；同一业务动作始终使用同一幂等键。旧项目展示了逐槽位资格判断、MES检查、Trace上传和有限重试意识，以及 RFID 失败降级临时条码、进站批量获取工站参数的链路，予以吸收；固定四槽、三次重试、深层跳转、禁用结果字段、字符串成功标记和调机用临时码的写死分支均未纳入。
