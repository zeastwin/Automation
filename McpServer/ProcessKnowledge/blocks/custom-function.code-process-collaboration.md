# 流程与自定义代码协作边界

## 可观察目标

流程与自定义代码各司其职：流程负责时序、互锁、IO 与运动；代码负责计算（可放位置、临时条码）、复杂协议收发（MES、功率、炉温）与界面呈现（数据显示、屏蔽开关）。两侧通过消息调用、开关标记和小型入口流程协作，边界清晰可审计。

## 适用边界

适用于需要代码能力的场景：位置/路径计算、非 trivial 协议解析、跨界面数据显示、UI 按钮触发的设备动作。能用流程原生指令表达的逻辑不进代码；代码不直接替代流程的互锁与安全判断。

## 当前事实与适配

需要：发送处理消息/发送及接收指令与代码处理器的路由契约、代码侧函数名与参数格式、用于联动的开关标记变量、UI 触发入口约定。历史代码函数名与参数格式不得臆测，须从代码证据核对。

## 参考阶段

1. 计算委托：流程在决策点调用代码计算（如"计算可放位置"），按返回结果分支。
2. 协议收发：流程触发代码完成设备通讯（获取功率、MES 报文），代码返回结果，流程保存并使用；收发失败按代码返回的错误分支处理。
3. 界面呈现：流程把过程数据（功率、胶重、报警）推送到界面显示，显示不参与控制判断。
4. UI 入口：界面按钮调用只有几条指令的小流程，置开关标记/索引，实际动作由常驻生产流程消费标记完成，入口流程不自生长。
5. 启动通知：主流程启动/停止时向代码发送屏蔽解除/生效消息，保证代码侧状态与流程模式一致。

## 完成证据

每次代码调用有返回并被检查；界面触发动作实际由生产流程执行且有完成反馈；代码异常时流程进入明确的失败分支而不是忽略返回值。调用未检查返回即继续为失效。

## 失败、超时与恢复

代码调用超时或异常返回按失败分支处理并报警；入口标记被置位但生产流程未消费时报警提示；代码侧崩溃不影响流程侧安全互锁（互锁不依赖代码）。

## 幂等与甄别结论

开关标记置位幂等；界面入口流程重复触发不重复执行动作（由标记消费保证一次）。旧项目在 UI 里内嵌长动作逻辑、代码直接操作设备绕过流程未被保留；消息路由+标记联动的分层、入口流程最小化、启动/停止通知代码被保留。
