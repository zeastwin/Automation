# 流水线工位三件套与状态机

## 可观察目标

流水线工位由一组配对流程构成：缓冲区流程持有九态状态机（Input_Ready→Input_Running→Input_Finish→Work_Ready→Work_Running→Work_Finish→Output_Ready→Output_Running→Output_Finish→回 Input_Ready），负责物料流入/流出与上下游要料；作业台流程承载工位状态与阻挡放行；作业流程只做本工位工艺，由状态机触发。三件职责分离，同一结构按工位复制。

## 适用边界

适用于多工位流水线（点胶/组装/复检/清洁/撕膜等）每站配缓冲的情形。单工位独立设备、机器人直接换料无流水线的场景不适用。多工位间工艺耦合（同载具多站接力）时配合 orchestration.single-robot-dispatch 或 transfer.station-handoff 使用。

## 当前事实与适配

需要：本站九态状态变量、进料/出料阻挡与到位感应、上游要料信号（物理 IO 或通讯 IO 二选一，运行前确定）、上游物料就绪感应。历史固定"四穴位"数量与固定状态数值不得复用；要料电平与屏蔽标志语义必须显式声明。

## 参考阶段

1. 进料 Ready：确认生产/调机模式；检查工艺前置（针头使用时长、胶水失效时间等耗材门控）与上游屏蔽标志，未屏蔽时向上游发要料信号（物理 IO 置电平或通讯写信号），等待物料流入到位。
2. 物料到位后依次推进 Input_Running→Input_Finish，期间结构体数据传递（SN/载具码随物料流转），把控制权交给 Work 段。
3. Work_Ready→Work_Running：启动本工位作业流程（等流程就绪→启动→等结束），完成后置 Work_Finish。
4. Output_Ready→Output_Running：出料阻挡按下游状态放行，检测流出到位后置 Output_Finish，回到 Input_Ready 循环。
5. 要料信号用完即清（置 1→等下游响应→清 0），并在工位忙（Work 中）时不发起新要料。

## 完成证据

九态状态机每个物料周期完整走一轮且回到 Input_Ready；上游物料到位与 Input_Finish 一致；作业流程只在 Work_Running 期间执行。状态跳变缺环或物料在非 Work 段被加工均为失效。

## 失败、超时与恢复

物料流入超时按自动处理重试或报警；要料信号发出后上游长期无响应报警并保持 Ready；报警处理步骤执行气缸回原与状态初始化后跳回第一步。状态机卡死时人工确认后复位到 Input_Ready。

## 反模式

- **作业流程直接改状态机**：作业流程绕过 Work 段调度自己改状态变量，状态机出现双写者 → 状态跳变不可追溯。状态只能由缓冲/作业台流程推进。
- **要料信号发完不清**：物料到位后要料信号残留为 1，上游持续送料造成堆料。置 1→确认响应→清 0 必须成对。
- **九态缺环复制**：复制工位时只复制了 Work 段漏了 Input/Output 段，物料到位但永远不进作业。三件套复制必须整体复制并逐项换前缀。
- **状态推进不带门控**：状态推进指令不带当前状态判断，重复执行或报警恢复后连跳两态。每步推进必须按当前状态门控。

## 幂等与甄别结论

状态推进指令按状态门控，重复执行无副作用；要料信号清零幂等。旧项目固定穴位数、固定延时 500ms、玻璃数量小于 4 的硬编码门槛未被保留；九态状态机、耗材门控前置、屏蔽标志过滤、IO/通讯双模要料、结构体随料流转被保留。
