# 变量设计总纲

## 可观察目标

跨流程的状态数据有一套一致的变量规划：变量按归属分层、按角色命名、有唯一的所有权与清零责任，多副本工位的变量天然隔离；任何变量在任意时刻都能回答"谁写、谁读、谁清零"。

## 适用边界

适用于多流程协作的整机程序（全流程平台与 PLC 主控-PC 代理形态均适用）。单条临时流程内部的局部计算变量不在本块；安全互锁变量的取值规则由平台安全契约决定，本块只管组织方式。

## 当前事实与适配

跨项目一致的变量分层（按归属，三层）：

1. **流程私有**：只被本流程读写的工作变量（当前步进索引、临时计算结果），不跨流程引用。
2. **跨流程握手/共享**：被多个流程按约定读写的状态（工位九态状态机变量、要料/给料握手信号、模式与屏蔽标志、更换料盘计数），写入方唯一、读取方多方，信号用完即清。
3. **常驻全局**：整机级状态（设备模式、上下游屏蔽登记、系统暂停变量），由系统服务或唯一所有者维护。

命名与隔离惯例：变量名带工位前缀+角色（工位状态/穴位占用/计数），同构多副本工位（左右站、1..N 号线、A/B 工位）复制时必须重写前缀，禁止跨工位引用对方私有变量（复制第二份时逐项核对前缀是历史踩过的坑）。状态机类变量（如工位九态）由推进该状态的流程独占写入；计数器变量只增/清由一个流程负责。载体身份类变量随物料流转，进出站流程负责绑定与删除，其他流程只读。

## 参考阶段

1. 盘点状态：列出所有跨流程状态（工位状态、握手信号、标志、计数、身份），按三层归类，确定每个变量的唯一写入者。
2. 命名落地：按"前缀+角色"重命名，多副本工位补序号/方位前缀。
3. 清零责任：每个握手信号与计数标注"用完即清"的负责流程；状态机变量标注合法迁移表。
4. 复制核对：复制同构工位流程时，同步复制变量并逐项替换前缀，验证无跨工位引用。

## 完成证据

任意变量在评审中能回答写入者、读取者、清零者三方；同构工位变量除前缀外结构一致；没有"两个流程都可写"的共享变量；握手信号无残留（用完即清）。

## 定量参考惯例

以下为跨项目归纳的典型量级，只作起步值与合理性检查；现场定型以实测量和用户确认为准，禁止照抄历史项目数值。

| 场景 | 典型起步值 | 说明 |
|---|---|---|
| 气缸/阻挡等本站动作反馈超时 | 1~5s | 超限按故障报警，不无限等待 |
| 跨机台/上下游握手超时 | 10~30s | 上限仍无响应报警并保持 Ready |
| 按钮/到位开关去抖 | 20~50ms | 去抖后还需释放确认（见 monitoring.system-service-listeners） |
| 通讯信号确认窗口 | 100~300ms | 按对端协议实际周期调整 |
| 通讯/读取类自愈重试 | 2~3 次 | 耗尽转故障分支 |
| 动作类重试 | 1~2 次 | 耗尽转人工确认，不静默跳过 |
| 工艺参数（延时/画圆/固化等） | 现场实测 | 模型只留配置位，不猜数值 |

计数类变量的量级检查：与实物对应（料仓容量、穴位数）必须来自现场结构或用户确认；纯逻辑计数（循环轮次）由业务目标推导。

## 失败、超时与恢复

变量语义不确定（归属不明）时先补清所有权再写流程，不靠运行试错发现；流程异常终止后由复位流程负责把握手/状态变量恢复初值——恢复清单在 variables 规划阶段一并产出。

## 反模式

- **双写者变量**：两个流程都能写同一状态变量，时序竞争下状态不可预期。唯一写入者是底线。
- **复制不改前缀**：左工位流程复制成右工位，变量还引用左边，两工位互踩状态。复制逐项换前缀。
- **握手信号不复位**：异常路径跳过了信号清零，下次启动带着残留信号误动作。清零责任进入复位恢复清单。
- **计数器既加又清**：生产流程加计数、报警流程清计数，中途清掉真计数。加与清归同一流程。
- **魔法数字状态**：状态变量用裸数字 3/4/9 表达状态且无迁移表，改状态机全靠猜。状态有枚举语义与合法迁移表。

## 幂等与甄别结论

标志置位/清零、计数清零均幂等；状态机迁移按合法迁移表执行，重复迁移同态无副作用。历史项目固定变量索引、跨工位复制未改前缀、A/B 机台硬编码分支不吸收；三层归属、唯一写入者、前缀隔离、用完即清、复位恢复清单被保留。
