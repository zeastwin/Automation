# 读取标识并绑定物理载体

## 可观察目标

一次读取事务结束后，当前物理载体及其有效槽位具有经过校验的身份记录；后续流程能证明该记录来自本次读取，而不是旧响应、其他载体或部分更新。

## 适用边界

适用于扫码枪、RFID 或同类读取设备。只读取设备字符串但不绑定物理对象、只做人工展示，或载体已经离开识别位置时，不使用本块。

## 当前事实与适配

开始前获取当前载体存在反馈、载体/槽位模型、读取协议、响应关联方式、允许格式、空值和重复码策略。槽位数量、字段顺序、成功标记和重试次数必须来自当前项目，不能沿用历史配置。

## 参考阶段

1. 固定当前载体上下文，生成本次读取标识；清理接收缓冲，但保留最后一份已提交的有效绑定。
2. 触发读取，在有界时间内接收与本次请求关联的完整响应。
3. 解析并校验格式、字段数、身份长度、重复关系和业务允许状态。
4. 在临时结果中建立载体、槽位和产品身份映射；任何一项失败都不提交部分映射。
5. 原子提交绑定记录，发布明确成功终态；失败则保留原有效记录并发布分类原因。

## 完成证据

完成必须同时具备：设备响应属于本次事务、载体仍在识别位置、全部必填身份通过校验、绑定记录一次性提交。发出读取命令、收到任意字符串或只修改成功变量都不等于完成。

## 失败、超时与恢复

区分无响应、响应不完整、格式错误、重复身份、业务拒绝、设备断开和载体移动。通讯类失败可在载体未移动且清除了本次临时响应时有限重试；“重试 N 次”表示首次读取之外最多再读 N 次，最大总尝试次数为 `1 + N`。手工计数时应在每次读取发起前增加总尝试次数，并以 `attemptCount < maxAttempts` 判断是否再试。数据或业务失败不得盲目重读覆盖。状态无法确认时阻止载体继续流转并保留诊断证据。

## 反模式

- **读旧响应当本次**：不清接收缓冲，读到上一载体的码绑到当前载体。每次事务生成本次读取标识并清理缓冲。
- **部分映射就提交**：载体码绑上了但槽位还没核，先提交再说。任何一项校验失败不提交部分映射。
- **载体已走还在绑**：读取超时后不确认载体位置就绑定。绑定前确认载体仍在识别位置。
- **失败盲目重读覆盖**：格式错误反复重读，把"读不到"拖成"读错也提交"。通讯类失败有限重试，数据/业务失败不重读。
- **成功标记先置后绑**：先把成功变量置 1 再慢慢写绑定记录，中断后出现"已成功但无绑定"的幽灵状态。绑定记录原子提交，终态最后发布。

## 幂等与甄别结论

同一读取事务重复执行只能得到同一提交结果；新事务不得复用旧接收缓冲。旧项目证明了“身份必须和载体/槽位一起处理”，但其固定槽位、深层跳转、超大单步骤、旧成功标记和具体长度规则均未纳入本规范。
