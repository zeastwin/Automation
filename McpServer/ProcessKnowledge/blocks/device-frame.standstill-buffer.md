# 静置中转设备框架

## 设备画像

为工件提供时间静置缓冲的中转设备：多仓位存储 + 进出料移栽 + 计时队列。存在两种调度形态——多线流水线式（每线独立状态机+阻挡接力）与单机器人搬运式（调度器三流向串行），按机械布局选择其一。

## 功能单元构成

| 单元 | 职责 | 典型流程 | 引用功能块 |
|---|---|---|---|
| 多线仓位 | 同构线复制、九态状态机、队列计时、自动靠拢 | 1..N 号线流程 | orchestration.replicated-station-fleet |
| 单机器人调度 | 要料分流、串行互斥、仓位记录、删除校验 | 调度流程+三流向执行流程 | orchestration.single-robot-dispatch |
| 进料移栽 | 接来料、阻挡接力放入 | 进料移栽流程 | transfer.station-handoff |
| 出料移栽 | 取出送下游、队列时间转移 | 出料移栽流程 | transfer.station-handoff |
| 追溯事务 | 进站生成记录、MES 出站、json 仓位记录联动 | 进出站流程 | identify.read-and-bind-carrier、transaction.submit-trace-record、custom-function.code-process-collaboration |
| 门禁与停止 | 门禁检测、集中停线 | 常驻+停止流程 | interlock.safety-gate-watchdog |

## 单元间衔接

多线式：载具入线→按位接力流入→起始时间入队尾→出料时队首时间转移出移栽→自动靠拢补位。单机器人式：调度循环查仓位记录+下游要料→串行启动某流向执行流程（前置三查+位置防呆）→取放后更新记录并校验删除。两种形态的共通契约：仓位记录与实物一致、每个出站载具可追溯到进站时间。

## 框架变化点

调度形态二选一（多线流水线 vs 单机器人三流向——由机械布局决定，不可混用）；线数/仓位数；仓位记录载体（变量/结构体/代码/文件四选一）；有无 MES 出站；虚拟 IO vs 实体 IO（运行前定一种）。

## 搭建顺序

复位族 → 门禁常驻 → 按选定形态建核心（多线式先建 1 条线再复制；单机器人式先调度骨架再逐流向填充）→ 进出移栽 → 仓位记录+MES → 集中停止收尾。

## 完成证据

静置时长达标的工件按先进先出出料（队列时间正确转移）；仓位记录数与实物一致；单机器人形态下同一时刻只有一个流向执行。

## 反模式

- **两种调度形态混建**：既有部分多线流程又有机器人调度流程，资源互相抢。形态二选一，另一种删除。
- **仓位记录只进不出**：进站生成记录、出站不删，可放位置计算逐渐失败。记录与实物账目一致是共通契约。
- **队列时间漏转移**：出料时没把队首起始时间转移到出移栽，静置时长统计失真。队列操作与到位感应成对。
- **先复制后验证**：1 号线没验证就复制出 N 条，骨架错误被复制 N 遍。先建一条完整线验证再复制。

## 黄金样例

> 来源：`BC_静置机0615虚拟IO修改(联丰)`。单机器人三流向形态的落地参考。

**流程族清单**（10 个流程）：复位总流程、主流程启动、门禁检测｜调度流程、取来料载具放静置台、取静置料放A机台、取静置料到B机台、BC进料作业台｜进站读取RFID、MES出站上传。流程数量极少但职责完备：一个调度器 + 三个执行流 + 一个作业台 + 系统服务 + 追溯，这正是单机器人形态"调度与执行分离"的最小实现。

**调度流程骨架**（5 步循环）：

| 步骤 | 职责 | 为什么这样排 |
|---|---|---|
| 判断要料信号 | 读下游各机台要料信号（历史为虚拟/实体 IO 两套判断并存——反面证据，当前只建实际使用的一种） | 目标选择先于一切动作；多目标同时要料时按优先级或顺延 |
| BC_A / BC_B 分支 | 按要料目标启动对应执行流程并等结束 | 分支对称，各执行流程前置三查（夹爪/有料/轴位） |
| Input 分支 | 无下游要料而来料可入时，取来料放静置台 | 下游不要料时补库存，仓位记录进站生成 |
| 循环回查 | 回到要料判断 | 每轮重新决策，不预生成整轮计划 |

**执行流骨架**（取静置料放A机台，3 步）：前置三查与位置防呆 → 取放轨迹（过渡→上方→进给→闭爪→上方→安全位）→ 更新仓位记录（删除已取仓位并校验删除成功）。理由：三查防的是"夹爪状态错、实际无料、轴位越界"三类事故；记录删除与校验放最后，失败弹框人工确认——机器人动作可以重做，账目错了整批混乱。

**BC进料作业台**（9 步）：即工位九态的标准展开（进料 Ready/Running/Finish → 工作 → 出料 → 报警处理），与三件套同构——静置机的"作业"就是静置计时，由队列/仓位记录承载。

## 幂等与甄别结论

框架只约束两种形态的构成与计时契约。旧项目 A/B 机台硬编码、固定线数 5、固定偏移 50/60/70、虚拟/实体双实现并存不吸收；两种调度形态各自被保留为可选模板、队列计时、记录删除校验被保留。
