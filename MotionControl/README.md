# 运动控制源码导航

`MotionControl/` 以 3.0 成熟运动模块为核心，直接接入 4.0 的实例级运行时。没有再建立 LegacyAdapter、应用适配层或第二套运动路由。该层不显示窗体和弹框；安全判断由平台安全协调器与调用方共同执行。

当前控制卡配置契约只允许一张 `雷赛总线卡`；不建立主站、从站或多卡拓扑。缺少控制卡时平台可按无运动硬件启动，已有配置为多卡或其他卡型时严格拒绝加载。

当前六轴工站类型固定为：轴工站、EPSON、汇川和汇川 V4。机器人直接作为六轴工站参与手动控制、流程资源互斥、点位与料盘操作，不需要伪造控制卡或物理轴。纯机器人项目允许在没有雷赛卡时启动。

| 目录 | 主要入口 | 职责 |
| --- | --- | --- |
| `Core/` | `IMotionRuntime`、`MotionCtrl`、`AxisStatusCache` | 运行契约、运动协调、六轴工站持有与轴状态缓存 |
| `Drivers/` | `LTDMC`、`LeiSei3000`、`Inovance/` | 雷赛与汇川原生 SDK 调用 |
| `Stations/` | `AxisMotionStation`、`EpsonStation`、`InovanceStation` | 3.0 六轴工站运行语义的直接实现 |

## 已保留的 3.0 行为

- 雷赛卡初始化时下载 `card_0.ini`，总线异常先软复位并重试。
- 程序启动后自动为无报警的轴上使能；这是方便操作人员开机即用的产品行为。
- 绝对值编码器轴通过 SDK 查询内部节点地址，读取 `0x6064` 并同步编码器位置和指令位置；不向用户暴露从站号。
- `HomeMethod <= 0` 时沿用 INI 回原方式，大于 0 时使用轴配置；回原成功按“编码器清零、等待 100ms、指令位置清零”执行。
- 普通整站点位或偏移运动中，任一轴出现报警、急停或正负硬/软限位，会联停本站全部轴。回原、单轴运动和找限位不误用这条联锁。
- 停止轴后最多等待 500ms 确认停稳；未确认停稳按故障处理。
- 机器人暂时离线不阻塞平台启动，后台按 3.0 行为持续重连；汇川连接后按配置加载控制器点位，EPSON 使用原命令表协议。
- 3.0 的 IO 用途完整保留为通用、急停、复位、启动、暂停、停止和刹车；急停输入和刹车输出使用逻辑值，`EffectLevel` 只在 IO 驱动中映射一次。
- 卡初始化内部自动上使能后立即采样急停，机器人工站初始化完成且即将放闸前再采样一次；确认全部物理轴上使能后放闸。
- 停机时既停止全部六轴工站，也逐一停止未绑定工站的已配置物理轴；确认停稳后抱闸再释放设备。
- 轴工站的流程点位、偏移与料盘运动直接复用 `AxisMotionStation`，保持同一套工站联锁和资源语义。

## 轴配置

- `EncoderType`：`Incremental` 或 `Absolute`。
- `HomeMethod`：`-1`/`0` 沿用 `card_0.ini`，正数直接传给雷赛总线回原接口。
- `NegativeSoftLimit`、`PositiveSoftLimit`：同时为 0 时沿用 INI；项目覆盖时必须同时配置且负值小于正值，驱动严格按负、正顺序传参。

## 实机验收清单

代码与无硬件测试不能替代以下现场确认：

1. 总线正常、断线和异常启动下的软复位、配置下载与错误码。
2. 各轴无报警自动上使能，报警轴不强行使能；轴使能确认后才放刹车。
3. 绝对值编码器断电重启后的 `0x6064` 位置同步，以及项目软限位正负方向。
4. 每种 `HomeMethod` 的实际搜索方式、速度、结果和清零顺序。
5. GO、MOVE、JOG、整站协调运动和流程料盘运动的减速停、急停及 500ms 停稳确认。
6. 急停和刹车在 `EffectLevel=正常/取反` 两种电气极性下的逻辑。
7. EPSON、汇川、汇川 V4 的连接、自动上使能、六轴点位、取点、料盘和断线重连。
